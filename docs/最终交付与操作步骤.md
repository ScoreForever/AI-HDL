## 3. 下载和复现

在 GitHub 选择交付分支，点击 Code → Download ZIP，解压后在工程根目录执行。不要把整个 GitHub 工程 ZIP 作为课程作业包提交。

已有 Icarus Verilog 的 Linux 或 WSL 环境可以使用系统工具：

```sh
export IVERILOG="$(command -v iverilog)"
export VVP="$(command -v vvp)"
# Debian/Ubuntu amd64 通常如下；其他系统按实际 ivl 安装目录填写。
export IVL=/usr/lib/x86_64-linux-gnu/ivl
python3 scripts/verify.py
python3 scripts/extended.py
```

`IVL` 目录应包含 `ivl`、`ivlpp` 等 Icarus 后端文件，路径错误会导致编译失败。在本次原云环境 `/workspace/AI-HDL` 下，直接运行上述两个 Python 脚本即可，工具已在 `/workspace/tools/iverilog`；现有安装脚本默认路径也指向 `/workspace/tools`，不要在任意机器上不加检查地照搬。

课程测试日志位于 `build/{winograd,cordic,fsm}/`，扩展日志位于 `build/extended/`。脚本抛出异常或退出非零都应先排查，不能只看某一行 PASS。

## 5. 在课程服务器完成 VCS/Verdi 复验

使用已经连通校园网/VPN 且配置好 SSH 身份的机器。连接信息和主机指纹核实要求见 `docs/交接说明.md`。在服务器创建全新的目录，传入本工程的 `lab1/`、`scripts/`、`docs/course_manifest.json`，保持目录层级；不要覆盖已有工作目录。工具和许可证初始化遵照服务器管理员说明。

进入新工程根目录：

```sh
command -v vcs
command -v verdi
python3 scripts/verify_vcs.py
```

脚本先检查官方文件哈希，再在 `build/vcs-时间戳/lab1/` 下依次运行三项原始 `make rerun`。成功时输出 Winograd/CORDIC 各 10 PASS，FSM 3 PASS，并保存 `summary.json`。每项目录有 `make.log`、`compile.log`、`simulation.log`。许可证等待行为由课程 Makefile 决定，等待过久请检查许可证环境，不要修改检查条件。

也可按官方流程分别执行：

```sh
(cd lab1/winograd/run && make rerun)
(cd lab1/cordic/run && make rerun)
(cd lab1/fsm/run && make rerun)
```

Winograd/CORDIC 在远程图形桌面中可运行 `make all` 并用 Verdi 的 Signal → Get All Signals 查看 FSDB。FSM 原 Makefile 没有 `all` 目标，不要套用。保存真实服务器日志和必要截图，将实际工具版本、日期、结果补入报告，再重新打包。

Bonus 的直接卷积参考由 `scripts/extended.py` 生成。若要使用 VCS 验证 Bonus，先运行扩展脚本生成向量与 TB，再在工程根目录执行：

```sh
cd build/extended
vcs -full64 -sverilog -top tb -o simv2 -l vcs2_compile.log stream2.sv ../../lab1/winograd_2d/src/winograd_2d.v
./simv2 -l vcs2_simulation.log
```

必须在有 `vectors2.txt` 的同一目录运行仿真。以上 VCS 命令在当前环境未实测；其预期输出为 `ALL PASS: 2D streaming 1200 cycles, 928 checked outputs`。
